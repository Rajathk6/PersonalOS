# ADR-002 — PostgreSQL 16 as System of Record

Status: Accepted
Date: 2026-10-08

## Context
Every important task/workflow must survive restart, power, and network loss (NORTH_STAR principles 4–5). Concurrent workers and future pgvector/multi-node need relational integrity. Locked stack for Phase 0 is PG16 + Prisma.

## Decision
PostgreSQL 16 is the sole system of record for tasks, workflows, queue rows, registries, and memory facts. All access goes behind repositories so a future store swap never leaks. Queue lives in PG (see ADR-004).

## Alternatives considered + why rejected
- SQLite-first: rejected — weaker concurrent-worker semantics and multi-node future; migration churn later.
- Mongo/dynamo-style NoSQL: rejected — loses integrity for money/tasks/retries; NORTH_STAR §8 demands relational.
- In-memory/JSON files: rejected — power-loss = data loss, violates persist-everything rule.

## Consequences
- Workflows persist id/status/checkpoint/retry/worker/timestamps per NORTH_STAR §4; boot recovers from DB.
- Adds Docker Compose for PG16 + Prisma migrations as Phase 0 baseline.
- Phase 0 must do differently: no direct SQL in app code (repositories only), design `tasks`/`queue` tables for leases before any worker code, verify with `docker restart db`.
