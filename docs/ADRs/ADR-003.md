# ADR-003 — ModelProvider Abstraction

Status: Accepted
Date: 2026-10-08

## Context
Hardware is i7/12GB Iris iGPU (~1Mbps): 3B easy, 7–8B quantized practical, 14B slow. Models will change; NORTH_STAR requires model/worker independence and a Model Registry with quality/cost/latency/privacy routing.

## Decision
App code never imports ollama/SDKs directly. All inference goes through `ModelProvider.generate(request)` behind a router that picks models by task-type/tool-support/HW/privacy. Registry holds metadata; discovery is inspect→compat→benchmark→recommend.

## Alternatives considered + why rejected
- Direct Ollama calls in app code: rejected — locks every feature to one model/host; blind replacement risk.
- One LLM process per role: rejected — wastes 12GB RAM; NORTH_STAR §1 says roles share models.
- Cloud-only default: rejected — violates ₹0 + offline-usefulness + privacy on 1Mbps link.

## Consequences
- Phase 2 Ollama lives in exactly one provider package; grep must show zero direct imports elsewhere.
- Enables Pi/laptop/GPU routing and future OpenRouter/llama.cpp without rewrites.
- Phase 0 must do differently: define `ModelProvider` + `ModelRegistry` interfaces with stub provider now, forbid model SDK deps in Core.
