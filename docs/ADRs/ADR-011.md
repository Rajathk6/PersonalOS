# ADR-011 — Structured Finance Storage

Status: Accepted
Date: 2026-10-08

## Context
NORTH_STAR §8: structured data stays relational; Net Worth = Assets − Liabilities computed deterministically. LLM explains, never invents numbers. Finance (accounts/transactions/bills/loans/assets/investments/budgets/subscriptions) is a first vertical. Selective indexing only.

## Decision
Money lives in relational tables with constraints; all totals/interest/budgets are deterministic code/Zod-validated queries, never LLM arithmetic. LLM only narrates precomputed results. Vectors (pgvector) only where semantic search genuinely helps, never for balances.

## Alternatives considered + why rejected
- LLM-computed totals: rejected — hallucinates rupees; unauditable, untestable.
- Everything-in-vector: rejected — destroys exactness, explicitly Rejected in NORTH_STAR.
- Spreadsheet/JSON files: rejected — no integrity, concurrent-write races, no audit.

## Consequences
- Finance capability in Phase 7 ships schema + migrations + deterministic calculators + tests first, chat second.
- Audit trail for money movement pairs with Permission Engine Ask-gate (ADR-007).
- Phase 0 must do differently: keep Core free of money logic, prove repository + Zod + Vitest pattern on Tasks so finance tables inherit it.
