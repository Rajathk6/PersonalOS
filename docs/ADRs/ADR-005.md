# ADR-005 — Scheduler/Queue/Worker Separation

Status: Accepted
Date: 2026-10-08

## Context
NORTH_STAR principle 2 is absolute: Scheduler → Task → Queue → Worker → Model/Tools; scheduler NEVER calls models directly. Mixing scheduling with execution breaks persistence, retry, and multi-node assignment.

## Decision
Three separate duties: Scheduler creates/enqueues tasks (one-time/recurring/deadline/event/monitoring + deps/priority); Queue persists/orders them; Workers poll, lease, execute via Model/Tools, and persist results. No direct scheduler→model/tool path.

## Alternatives considered + why rejected
- Scheduler calls Ollama directly: rejected — bypasses permissions, queue, audit; explicitly listed under Rejected.
- Worker embeds scheduling logic: rejected — duplicates cron state, breaks coordinator/worker split for Pi future.
- Monolithic run-to-completion handler: rejected — no resume after power/model failure.

## Consequences
- Enables Phase 5 recurring jobs and Phase 8 Pi-coordinator/laptop-worker split unchanged.
- Failures are structured (`ToolResult` with retryable flag), never corrupt state.
- Phase 0 must do differently: scaffold scheduler as enqueue-only stub, implement worker poll loop in Bundle 0C, add lint/test asserting scheduler has zero model/tool imports.
