# ADR-009 — Multi-Node Worker Architecture

Status: Accepted
Date: 2026-10-08

## Context
Future is Pi = always-on coordinator (API/DB/scheduler/queue/memory/notify) and laptop = on-demand heavy worker (Ollama), phone = thin client (NORTH_STAR §11). Laptop must never be source of truth; Wake-on-LAN is optional, never foundational.

## Decision
Workers register, advertise capabilities (e.g. pi: db/light-compute; laptop: local_llm/coding), heartbeat, and receive capability-matched assignments. No hard-coded hosts/URLs/models/schedules — all via config + registry. Offline detection + reassignment are first-class.

## Alternatives considered + why rejected
- Hard-coded hosts/IPs: rejected — breaks on DHCP/laptop-sleep; blocks Pi/GPU evolution.
- Laptop-as-source-of-truth: rejected — sleeps/dies; explicitly Rejected in NORTH_STAR.
- Single-node-only code: rejected — forces rewrite in Phase 8; registration is cheap now.

## Consequences
- Phase 8 becomes config + placement, not rewrite; future GPU worker just advertises `large_llm`.
- Coordinator survives worker loss; tasks re-lease and reassign.
- Phase 0 must do differently: define `WorkerRegistry` (id/capabilities/heartbeat) with single local worker, keep all endpoints/models in env config, never literals.
