# ADR-008 — Local-First + Network-Aware

Status: Accepted
Date: 2026-10-08

## Context
Reality is ~1Mbps, power cuts, ₹0 budget (NORTH_STAR §9). Power/internet loss are normal conditions, not exceptions. Heavy reasoning stays local on quantized models; offline usefulness is a success metric.

## Decision
System is local-first and network-aware: tasks can enter WAITING_FOR_NETWORK and resume on `network.available`; fetch layers use cache/dedup, resumable downloads, and idempotent notifications. No mandatory cloud dependency.

## Alternatives considered + why rejected
- Cloud-first (APIs for core reasoning): rejected — fails on 1Mbps/outage, recurring cost, privacy loss.
- Pretend network is reliable: rejected — causes blind retries, duplicate alerts, corrupt downloads.
- Full-offline only (no network states): rejected — jobs/stocks/email genuinely need net; must wait, not fail.

## Consequences
- Scheduler/queue state machine includes `waiting_for_network`; events drive resume.
- Cache + dedup reduce bandwidth; resumable fetch survives power cuts.
- Phase 0 must do differently: add WAITING_FOR_NETWORK to Task states, config must allow offline boot, Bundle 0C tests kill+offline resume.
