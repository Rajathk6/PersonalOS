# ADR-007 — Permission Engine as Security Boundary

Status: Accepted
Date: 2026-10-08

## Context
NORTH_STAR principle 7: model is never the security authority. Shell and money/email/sysconfig actions are high-stakes; permissive model must not equal permissive access. Every tool declares permission reqs + risk (Low/Med/High/Critical).

## Decision
Model proposes, engine disposes. A central Permission Engine gates every tool call with Allow/Confirm/Deny, risk classification, sandboxing, and append-only audit trail. Defaults: auto web-search/read-own-data/draft; ask for send-mail/money-movement/destructive-shell/sysconfig.

## Alternatives considered + why rejected
- Model self-policing via prompt: rejected — jailbreakable, unauditable, violates security-boundary rule.
- Per-tool ad-hoc checks: rejected — inconsistent UX, gaps for new tools, no central audit.
- Allow-all locally ("my machine"): rejected — one bad plan deletes data or moves money.

## Consequences
- All Phase 3 tools (fs/shell/git/notify/mail) ship with risk + permission metadata + `ToolResult` errors.
- User confirmations become events (`user.confirmation.required`) phone-approvable in Phase 9.
- Phase 0 must do differently: define `PermissionEngine` + `Tool` interfaces and audit schema now, even before real tools exist.
