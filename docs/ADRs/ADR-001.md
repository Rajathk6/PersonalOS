# ADR-001 — Modular Monolith over Microservices/K8s

Status: Accepted
Date: 2026-10-08

## Context
PersonalOS is a local-first single-user system on one laptop (i7/12GB, ₹0 budget). NORTH_STAR principle 10 requires simple implementation with strong boundaries, not distributed ops overhead.
Spec explicitly lists microservices/K8s day one under Rejected.

## Decision
Ship a single deployable modular monolith with strict module boundaries (Core/Task/Queue/Worker/Model/Tool/Capability/Permission). Use npm workspaces packages only when a module earns it; Phase 0 starts minimal.

## Alternatives considered + why rejected
- Microservices + K8s: rejected — massive ops/memory cost, harder power-loss recovery, zero benefit for one user.
- Dozens of empty packages upfront: rejected — fake modularity, import cycles, slows Phase 0.
- Unstructured monolith (no boundaries): rejected — guarantees orchestrator rewrite when capabilities arrive.

## Consequences
- Enforces acyclic imports; Core stays generic and stable per NORTH_STAR §3.
- Defers split until measured pain (load, team, deploy); split is extract-package, not rewrite.
- Phase 0 must do differently: cap at ≤6 packages (`apps/api` + core/contracts), add `npm run typecheck` cycle check, reject PRs adding services/K8s/Redis.
