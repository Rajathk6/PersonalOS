# RISKS — Top 12 (plain language)

| # | Risk | Likelihood | Impact | Mitigation | Phase it bites |
|---|---|---|---|---|---|
| 1 | Power cut in the middle of a task; on reboot you can't tell what finished | High (cuts are normal here) | High (lost or double-done work) | Persist task + step + checkpoint on every transition; leases expire so a dead worker's task gets reclaimed; boot runs recovery before new work | 0–1, proven in 5 |
| 2 | Ollama on the Iris iGPU is too slow, everything feels broken | High (no NVIDIA, 12GB RAM) | Med (bad demos, wrong conclusions about design) | Keep model behind `ModelProvider`; Phase 0–1 use stubs/mocks; measure tokens/sec before promising any UX; small models first | 2 |
| 3 | Postgres goes down (container killed, disk full, bad restart) and nothing works | Med | High (whole system stops) | Docker volume for data; health check + clear boot order (DB → recover → scheduler → workers); Phase 0 verify includes `docker restart db` test | 0 |
| 4 | A retried task does its side effect twice (two emails, two file writes, double notification) | Med | High (user stops trusting the system) | `idempotency_key` UNIQUE on tasks; tools written to be safe-to-retry; checkpoint says what already happened; audit log to detect doubles | 1, 3, 5 |
| 5 | A clever prompt talks the model into doing something forbidden ("ignore rules and delete…") | Med | Critical (data loss / security hole) | Model is never the boss: Permission Engine (Allowed/Confirm/Denied) gates every tool; shell is proposed → classified → sandboxed → audited | 3–4 |
| 6 | Scope creep: building phone app / multi-node too early while core is still shaky | High (it's tempting) | High (thin effort, nothing solid) | Hard phase gate: phone (9) and multi-node (8) stay thin-client/registry-only until core + recovery tests pass; say no without an ADR | 8–9 |
| 7 | Putting everything into vectors ("vector-everything") instead of plain tables | Med | Med (slow, wrong answers, wasted effort) | Rule: structured facts stay in Postgres; pgvector only where meaning-based search truly helps; selective indexing with freshness scores | 6 |
| 8 | Machine names / IPs / model names typed directly into code, breaks on the next machine | Med | Med (works on laptop, dies on Pi) | No hard-coded hosts: workers register + heartbeat + advertise capabilities; config from env; grep for IPs/model names in review | 0, 8 |
| 9 | Swapping to a new model quietly makes answers worse and nobody notices | Med | Med (silent quality drop) | Never blind-swap: Model Registry discovery flow (compat → cost → tool-check → benchmark → compare → recommend); pin model ids in config | 10 (starts 2) |
| 10 | After 3 days offline, the scheduler fires 3 days of missed reminders Scans/notifications at once | Med | Med (spam storm, duplicates) | Catch-up is semantic: one task with `{since: last_checkpoint}` + dedup, policies `since-last-success / skip / once`; never blind replay | 5 |
| 11 | Letting the LLM do money math ("net worth is roughly…") and getting wrong numbers | Med | High (wrong money = harmful) | LLM explains, Postgres/Python computes: Net Worth = Assets − Liabilities in code, never in prose; finance tables deterministic | 7 |
| 12 | Asking "are you sure?" for everything, so the user starts clicking Yes blindly | High | Med (approvals become useless) | Confirm only what matters (send email, money moves, destructive shell, deletes of user files); everything safe is auto-allowed; keep the ask-list short | 3–4 |
